# Chorus / 对话场 — MVP PRD (v1)

> 一句话定义：**一个由主持人控场的多角色 AI 对话空间。**
>
> 面向用户的话术：**和你想见的人物，在一个不会冷场的 AI 房间里对话。**

---

## 0. 这份 PRD 的定位

- **概念级**，不写实现细节，不锁死调度算法
- 范围：MVP v1（你 + 主持人 + 1 个角色）
- 目标读者：工程师 / Claude，能据此搭出可分享给 3-5 个朋友试用的 Next.js Web 应用

---

## 1. 验证假设

第一版只验证一句话：

> 「**多角色 + 主持人 + 用户** 的对话，是否明显比单个 AI 更有意思、更顺、更有参与感。」

如果验证不通过，整个产品方向需要重审。所以 MVP 不做任何与这个问题无关的功能。

**判断信号**（朋友试用阶段定性观察即可，不做埋点）：
- 是否有人主动说"想再玩一次"
- 单次会话长度（轮次）是否明显超过同等 GPT/Claude 直接对话
- 是否有"原来 AI 之间还能这样配合"的反馈
- 是否有"主持人多余 / 角色不像"的负反馈

---

## 2. 核心角色

| 角色 | 职责 | 不做什么 |
|------|------|---------|
| **用户** | 任意时刻可发言、可打断、可选话题 | — |
| **主持人 (Host)** | 节奏控制：开场、引导、转场、冷场接话、偶尔总结 | 不做知识输出主体，不长篇发言 |
| **角色 (Role)** | 提供观点 / 视角 / 个性，按角色设定回应 | 不抢主持权，不长期跑题 |

**关键：主持人 ≠ 角色**。主持人是"轻主持"，发言短、节奏感强、不喧宾夺主。

---

## 3. 信息架构（页面）

### 3.1 首页 `/`

- Slogan + 一句话产品介绍
- "创建房间"按钮（主 CTA）
- 极简登录或免登录（试用阶段）：用 nickname + 临时 token，浏览器本地存
- **"我的"入口**：累积展示历次会话的总结卡片（按时间倒序），点进去能看完整对话历史

### 3.2 建房流程 `/new`

三步走，单页内分段：

1. **选模式**（3 选 1，互斥）
   - 访谈模式
   - 对谈模式
   - 教练模式
2. **选角色**
   - 4 个内置模板（卡片式，首字母圆形头像 + 颜色编码）
     - 苏格拉底式追问者
     - 乔布斯式产品观点者
     - 温柔陪伴型角色
     - 严厉教练型角色
   - **"自定义角色"入口**（v1 包含）
     - UI = 维度组合式，不是单一 textarea
     - 3-5 个维度（具体维度由实现阶段定，候选：关系 / 性格 / 状态 / 职业 / 口吻 ...）
     - 每个维度提供选项卡片
     - 可加"随机一组"按钮一键生成
     - 末尾保留"补充描述（可选）"自由文本框作兜底，给想精确控制的用户留口子
     - 后端把维度选择 + 自由描述拼成统一 system prompt
3. **设话题**（可跳过）
   - 一句话起手话题。空着也能进。

底部 CTA："进入房间"。

### 3.3 房间页 `/room/[id]`

核心三区：

```
┌──────────────────────────────────────┐
│ 顶栏：模式 · 角色名 · 退出 · 结束并总结  │
├──────────────────────────────────────┤
│                                      │
│         对话流（消息按时间）            │
│         - 主持人发言                  │
│         - 角色发言                    │
│         - 用户发言                    │
│                                      │
├──────────────────────────────────────┤
│ 状态条：当前发言者 · "X 想补充" 提示    │
├──────────────────────────────────────┤
│ 输入框（用户随时输入）                 │
└──────────────────────────────────────┘
```

### 3.4 总结页 `/room/[id]/summary`

会后轻总结，由主持人**一次调用结构化输出**生成：

- 本轮聊了什么（2-3 句）
- 角色给了哪些关键观点（要点列表）
- 你的关键表达（1-2 条）
- **金句 / Take-away**（1-3 条）
  - 从对话里挑最能"被分享出去"的话（角色说的或你说的）
  - 卡片样式，可复制
- 1-3 条可继续追问的话题
  - 每条带"用这个开新房间"快捷入口

**操作**：
- "导出 Markdown"：单文件下载
- 自动沉淀到"我的"列表（首页可访问）
- "再来一场"按钮回首页

**不做**：图片导出（v1.5 再考虑）、用户编辑总结。

## 4. 核心机制（概念级，不锁实现）

### 4.1 话轮调度

**MVP 用最简版**：

> 每轮结束后，主持人 LLM 决定下一个发言者（自己 / 角色 / 等用户）。

- 输入给主持人的判断材料：模式、最近 N 条消息、用户是否刚发言、当前节奏（连续 AI 发言次数）
- 输出：`next_speaker ∈ { host, role, await_user }`
- 不做打分函数、不做角色"自请发言权重"，全交给主持人 LLM 一个决策点
- 后续若不够智能，再迭代成多 agent 协商

**硬规则**（不交给 LLM）：
- 用户发消息时，**立刻打断**当前 AI（前端中止 streaming）
- 连续 AI 发言不超过 3 轮，必须 await_user
- 用户连续等待 > 一定时间（例如 8 秒无输出），主持人接话防冷场

### 4.2 用户随时插入

- 输入框始终激活
- 用户提交消息 → 前端中止当前 streaming → 后端把用户消息插入历史 → 调度交给主持人

### 4.3 发言可见性

状态条只显示一行，三类信息：

- `主持人正在说...`
- `苏格拉底正在说...`
- `主持人准备总结 · 苏格拉底想补充`（"想补充"只是营造活感，不一定真触发，由主持人决定要不要给角色话筒）

### 4.4 模式差异

模式只影响**主持人 prompt 模板**和**默认调度倾向**：

| 模式 | 主持人风格 | 默认倾向 |
|------|-----------|---------|
| 访谈 | 像记者，向角色提问 | 多让角色说，用户随时插话 |
| 对谈 | 偶尔引导，不抢戏 | 多让角色和用户对话，主持人轻 |
| 教练 | 帮用户拆解问题 | 主持人多说，角色提供具体反馈 |

### 4.5 角色

- 内置模板 = 一段写好的 system prompt + 头像 + 显示名
- 自定义角色 = 用户给一段人设描述，系统包装成 system prompt
- 角色不感知"主持人"角色概念，只看到对话历史；调度由主持人独立完成

### 4.6 会话存储

- 每个房间一个 session id
- 服务端持久化**完整对话历史 + 总结**（朋友试用阶段够用即可，单租户 DB / Redis / 文件均可）
- 总结是独立实体，关联 session id，可单独查询展示
- 用户 nickname + 浏览器 token 作为身份；不做正式注册登录

### 4.7 LLM Provider 抽象

- v1 实现 provider interface 抽象层，支持多家可切（Claude / OpenAI / Gemini / 国产等）
- **切换是配置级别（环境变量），UI 不暴露**——朋友试用阶段没人需要选模型
- Provider 清单和实现可参考 `~/dev/github.com/openclaw/openclaw`，已有多家 provider 接入
- 主持人和角色可以用同一个 provider，也可以分别配置（实现层支持，配置默认相同）

## 5. v1 范围（要做）

- [ ] 首页 + 建房 + 房间 + 总结四个页面
- [ ] 主持人 + 1 个角色 + 用户的三方对话
- [ ] 4 个角色模板 + 自定义角色入口
- [ ] 3 种模式
- [ ] 最简话轮调度（主持人 LLM 单决策点 + 三条硬规则）
- [ ] 用户随时打断
- [ ] 状态条显示当前发言者 + "想补充"提示
- [ ] 会后总结
- [ ] "我的"页面：累积展示总结卡片，点入可看完整历史
- [ ] LLM provider 抽象层（不做 UI 选择，配置切换）
- [ ] 总结导出为 Markdown
- [ ] 朋友试用方式：**各自建房，不做分享/旁观/接管**

> 多人/分享类功能不在 v1 范围。验证假设是"产品本身有没有意思"，每人独立体验即可获得独立样本。

---

## 6. v1 不做（明确刀口）

- 多于 1 个角色 AI 常驻 → v1.5
- 语音输入输出 → v2
- 复杂世界观 / 长期记忆
- 角色之间长篇辩论
- 时间轴可视化
- 角色市场 / 社区
- 真实账号系统 / 付费 / 配额
- 移动端深度适配（先桌面优先，移动可看不可怕丑）

---

## 7. v1.5 / v2 路线（占位，不展开）

- **v1.5**：第二个角色常驻 · "谁想说"更细可视 · 更细的主持风格档位
- **v2**：语音 · 更多角色 · 角色并行预思考 · 长期记忆
